# 06 · 国际化与本地化

## 1. 范围

需要本地化的面：界面、CLI 输出、右键菜单、安装器、系统通知、错误信息、文件关联描述、帮助文档。核心原则：**所有用户可见文本都来自资源文件，代码中不出现硬编码文案。**

## 2. 语言清单与优先级

| 阶段 | 语言 |
|---|---|
| v1.0 | `zh-CN` 简体中文、`zh-TW` 繁体中文、`en-US` 英语、`ja-JP` 日语 |
| v1.1 | `ko-KR`、`de-DE`、`fr-FR`、`es-ES`、`ru-RU`、`pt-BR` |
| v1.2 | `zh-HK`、`it-IT`、`pl-PL`、`tr-TR`、`vi-VN`、`uk-UA`、`ar-SA`（RTL）、`he-IL`（RTL） |

- 开发源语言为 `en-US`（键的默认值），`zh-CN` 由核心团队同步维护为一等语言；二者在 CI 中都不允许缺键。
- 其他语言由翻译平台与社区维护，缺键回退到 `en-US`。

## 3. 资源组织

```
locales/
├─ fallbacks.json            # 回退链：zh-HK → zh-TW → zh-CN → en-US …
├─ glossary.csv              # 术语表（供翻译平台导入）
├─ en-US/
│  ├─ common.json            # 通用：确定 / 取消 / 文件 / 大小 / 日期
│  ├─ home.json
│  ├─ browser.json
│  ├─ compress.json
│  ├─ extract.json
│  ├─ mount.json
│  ├─ settings.json
│  ├─ errors.json            # 错误码 → 文案（与 Rust 错误码目录对齐）
│  ├─ formats.json           # 格式名、方法名、能力描述
│  ├─ shell.ftl              # Rust 侧：右键菜单文案（Fluent）
│  └─ cli.ftl                # Rust 侧：CLI 输出（Fluent）
├─ zh-CN/ …
└─ ja-JP/ …
```

- 前端按命名空间懒加载（打开设置页才加载 `settings.json`）。**M1 实现**：每种语言一个 `app.json`（约 390 键），四种语言全部打包进前端，切换语言无需加载；语言数增加后再按语言拆分懒加载。
- 键名：点分层级 + camelCase 叶子，例如 `browser.toolbar.extractTo`；禁止用整句作键。
- 每个键可附 `"_context"` 说明（提取工具会带给翻译者）。

## 4. 消息格式：ICU MessageFormat

```json
{
  "browser.status.selection": "{count, plural, =0 {未选择} other {已选 # 项（{size}）}}",
  "extract.conflict.title": "{name} 已存在",
  "job.eta": "{seconds, plural, other {剩余 # 秒}}",
  "compress.estimate": "预计 {from} → 约 {to} · 约 {duration}",
  "mount.ready": "已挂载到 <b>{mountPoint}</b>"
}
```

规则：
- 中文、日文只有 `other` 分支，但仍必须写 plural 语法，确保其他语言可扩展为 `one` / `few` / `many`。
- 禁止字符串拼接；所有变量命名，不用位置参数。
- 富文本用 `<b>`、`<a>` 标签配合 `Trans` 组件，不在资源中放 HTML 属性。
- 标点随语言（中文全角、英文半角），不在代码中追加标点。
- 文本膨胀预留：德语 / 俄语约 +30%，按钮不定宽，表格表头可省略号并带 tooltip。

## 5. 运行时行为

| 环节 | 设计 |
|---|---|
| 语言检测 | `settings.language`（显式）→ 系统界面语言（Windows `GetUserPreferredUILanguages`、macOS `AppleLanguages`、Linux `LANGUAGE` / `LC_MESSAGES` / `LANG`）→ `en-US` |
| 回退链 | `fallbacks.json` 声明，例如 `zh-HK → zh-TW → zh-CN → en-US`、`pt-PT → pt-BR → en-US`、`es-MX → es-ES → en-US` |
| 热切换 | `i18next.changeLanguage()` 触发重渲染；同时通知 Rust `LocaleService` 更新并写入配置，CLI / 右键菜单下次调用即生效 |
| 字体 | `<html lang>` 随语言变化，CSS `:lang(zh-CN)` / `:lang(zh-TW)` / `:lang(ja)` / `:lang(ko)` 切换 CJK 字体栈（苹方 / 雅黑 / Noto Sans CJK SC·TC·JP·KR） |
| 日期 / 数字 | `Intl.DateTimeFormat` / `Intl.NumberFormat` / `Intl.RelativeTimeFormat`，格式区域可独立于界面语言设置 |
| 文件大小 | 用户可选 KB（1000）/ KiB（1024）；默认按平台习惯：Windows 以 1024 进制显示 "KB"，macOS 1000 进制，Linux 显示 KiB |

## 6. Rust 侧本地化

- **核心库不返回文案**：错误为 `OmniError { code: ErrorCode, params: BTreeMap<&'static str, Value> }`，例如 `ErrorCode::WrongPassword`、`ErrorCode::PathEscapesDestination { path }`。GUI 用 `errors.json`、CLI 用 `errors.ftl` 渲染。
- **CLI**：`fluent-bundle` + `fluent-langneg` 协商语言；`--lang` 参数可覆盖；`NO_COLOR` / `LANG=C` 下输出 ASCII 安全文本。
- **Windows Shell 扩展**：FTL 资源用 `include_str!` 内嵌；语言优先级 = `config.toml` 中的语言 → `GetUserDefaultUILanguage()`；文案缓存按配置文件修改时间失效。
- **Linux 菜单文件**：构建脚本从 `shell.ftl` 生成 `Name[zh_CN]=…`、`Name[ja]=…` 行；nautilus-python 扩展使用 gettext `.mo`（同样由 FTL 生成）。
- **macOS**：从 FTL 生成 `ServicesMenu.strings`、`InfoPlist.strings`、Finder 扩展的 `Localizable.strings`。
- **一致性校验** `scripts/i18n-check`：JSON 与 FTL 键集合一致、缺键 / 未使用键、ICU 语法、占位符名称一致、禁止源语言与目标语言完全相同的未翻译项（白名单除外）。CI 失败阻断合并。

## 7. 排序、搜索与输入

- 列表排序在 Rust 端使用 ICU4X `icu_collator`，按当前区域规则排序（中文拼音、日文假名、德语变音、土耳其语 i），并启用自然排序（`file2` < `file10`）与大小写折叠。**M1 实现**：`omnizip-core` 的 `natural_cmp`（自然排序 + 大小写折叠，按 Unicode 码位），区域规则排序随 ICU4X 在 M3 接入。
- 搜索：Unicode 规范化（NFC）+ 大小写折叠；中文支持拼音首字母匹配（可选，`pinyin` crate）。
- 文件名显示强制 LTR 隔离（`<bdi>` / `unicode-bidi: isolate`），避免 RTL 语言下路径顺序错乱。
- 输入法：搜索框与重命名支持组合输入（`compositionstart/end`）期间不触发过滤。

## 8. RTL 支持（架构预留，v1.2 落地）

- 全部布局使用 CSS 逻辑属性（`margin-inline-start`、`inset-inline-end`）。
- 根节点 `dir="rtl"` 时：侧栏在右、面包屑箭头镜像、进度条方向翻转。
- 图标镜像白名单：箭头、面包屑分隔、撤销 / 重做、列表缩进指示；不镜像：勾选、播放、时钟。
- 字体：阿拉伯语 Noto Naskh Arabic / Segoe UI；希伯来语 Noto Sans Hebrew。

## 9. 翻译流程

| 环节 | 方案 |
|---|---|
| 平台 | Weblate（自托管）或 Crowdin；与 Git `l10n` 分支双向同步，每周合并到主干 |
| 术语表 | `glossary.csv`：压缩包 archive、解压 extract、压缩 compress、分卷 volume、固实 solid、条目 entry、挂载 mount、字典 dictionary、恢复记录 recovery record … |
| 上下文 | 键的 `_context` + 自动截图（Playwright 按键名定位元素截图并上传） |
| 字符串冻结 | 发布前 2 周冻结；紧急修复需翻译负责人批准 |
| 预翻译 | 机器翻译预填 + 人工审校；审校通过的才进入发布 |
| 贡献 | 社区贡献需 CLA；每语言至少 1 名审校者 |

## 10. 伪本地化与测试

- `en-XA`：加重音、扩展 40%、首尾加括号，用于发现硬编码与布局溢出。
- `ar-XB`：伪 RTL，用于发现方向性问题。
- 开发模式下缺键显示为 `[missing:key]` 并在控制台告警。
- Playwright 检查每语言关键界面的 `scrollWidth > clientWidth`（文本溢出）与截图回归。
- 单元测试覆盖 ICU 复数分支与错误码渲染。

## 11. 安装器与系统面

- Windows：MSIX manifest 多语言资源（`DisplayName`、文件类型描述）；NSIS 使用语言文件并按系统语言预选。
- macOS：`InfoPlist.strings`（Bundle 名、UTI 描述）、Services 名称。
- Linux：`.desktop` 的 `Name[xx]` / `Comment[xx]`、MIME XML 的 `<comment xml:lang="xx">`。
- 系统通知、Jump List、Dock 菜单均使用当前语言。
