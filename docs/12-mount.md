# 12 · 虚拟挂载：把任意压缩包当作磁盘使用

## 1. 目标

像 Windows 双击 ISO 得到一个盘符、macOS 双击 DMG 得到一个卷那样，**OmniZip 能读取的任何压缩包都可以一键挂载为虚拟卷**，内容按需解压、不落盘整包：

| 平台 | 挂载形态 | 文件管理器表现 |
|---|---|---|
| Windows | 盘符（默认从 Z: 向前取空闲）或 NTFS 目录挂载点 | 资源管理器"此电脑"与侧栏显示，可"弹出" |
| macOS | `/Volumes/<名称>` | Finder 侧栏与桌面显示，可"推出" |
| Linux | `/run/media/$USER/<名称>`（有 udisks 权限）或 `$XDG_RUNTIME_DIR/omnizip/mnt/<名称>` | 文件管理器侧栏显示（`x-gvfs-show`），可"卸载" |

典型用途：直接从 50 GB 的包里播放一个视频、用 IDE 打开包内源码、挑几张图、比对两个版本，而不必先解压。

## 2. 用户体验

- **入口**：命令栏"挂载"按钮；右键菜单"挂载"；CLI `omnizip mount`；可把 ISO / IMG 的双击默认动作设为"挂载"（与系统行为一致，需用户确认）。
- **一键默认**：不弹选项，挂载后自动在文件管理器打开；卷名 = 压缩包名去扩展名（非法字符替换）。
- **高级选项**（弹出面板）：挂载点 / 盘符、允许写入（临时可写层，卸载时保存到压缩包或放弃，§6）、卷标、退出应用后是否保持、缓存上限、"离线属性"（避免资源管理器自动读取内容生成缩略图）。
- **管理**：侧栏"已挂载"分组列出全部挂载（名称、挂载点、缓存占用、打开、卸载）；状态栏挂载徽标；托盘 / 菜单栏图标菜单"卸载全部"；系统原生的"弹出 / 推出 / 卸载"同样生效并同步回 UI。
- **加密包**：挂载时询问密码；密钥仅驻留守护进程内存，卸载即清零。
- **源文件变更**：压缩包被修改 / 删除 / 移动 → 自动卸载并通知。Windows 上对源文件加共享读锁阻止删除；macOS / Linux 用 inode 监视。
- **固实包提示**：首次访问需解压整个固实块。挂载前显示预计时间，提供"后台预热"（按块顺序预解到缓存）。
- **退出行为**：默认退出应用时卸载全部；可选"保持挂载"（守护进程常驻，托盘保留入口）。
- **恢复**：登录后可选自动重新挂载上次的卷。

## 3. 平台后端

| 平台 | 主后端 | 备选 | 说明 |
|---|---|---|---|
| Windows | **WinFsp**（`winfsp` crate） | ProjFS（系统内置"投影文件系统"，无驱动，但只能投影到 NTFS 目录且会在磁盘留占位文件）；Dokany | WinFsp 性能与兼容性最佳（rclone、Cryptomator、SSHFS-Win 同款），支持盘符与目录挂载点、异步 I/O。需安装一次签名驱动：安装器提供可选组件，或首次使用时按需下载并校验签名与哈希。许可：GPLv3 + FLOSS 例外；OmniZip 采用 MIT 开源，符合该例外，可直接使用 |
| macOS | **FSKit** 文件系统扩展（macOS 15+） | 进程内 NFSv3 服务 + `mount_nfs localhost`（`nfsserve` crate，零安装）；macFUSE（若用户已安装） | FSKit 为 Apple 官方用户态文件系统框架，无 kext，需用户在"系统设置 → 文件系统扩展"启用。对非块设备（虚拟）资源的支持程度需在 M0 验证；NFS 回环方案无需安装、macOS 12+ 全可用，作为保底 |
| Linux | **FUSE3**（`fuser` crate，直接对接 `/dev/fuse`） | — | 依赖 `fusermount3`（各发行版标配）；Flatpak 沙箱内不可用，设置页提示改用 .deb / .rpm / AppImage |

统一接口：

```rust
pub trait MountBackend: Send + Sync {
    fn capabilities(&self) -> BackendCaps;   // DRIVE_LETTER | DIR_MOUNTPOINT | WRITABLE | SYMLINKS | CASE_SENSITIVE | XATTR
    fn health(&self) -> BackendHealth;        // Ready | NotInstalled | NeedsEnable | VersionMismatch
    fn mount(&self, fs: Arc<dyn VirtualFs>, opts: &MountOptions) -> Result<MountHandle>;
    fn unmount(&self, h: MountHandle, force: bool) -> Result<()>;
}

pub trait VirtualFs: Send + Sync {
    fn lookup(&self, parent: NodeId, name: &OsStr) -> Result<Attr>;
    fn getattr(&self, node: NodeId) -> Result<Attr>;
    fn readdir(&self, dir: NodeId, cursor: u64, max: usize) -> Result<Vec<DirEntry>>;
    fn open(&self, node: NodeId, flags: OpenFlags) -> Result<FileHandle>;
    fn read(&self, fh: FileHandle, offset: u64, size: u32) -> Result<Bytes>;
    fn release(&self, fh: FileHandle);
    fn readlink(&self, node: NodeId) -> Result<PathBuf>;
    fn statfs(&self) -> Result<FsStats>;
    // 可写（ZIP overlay，v1.x）：create / write / unlink / rename / setattr / fsync
}
```

`ArchiveFs` 实现 `VirtualFs`，复用 `omnizip-core` 的 `TreeIndex`（目录结构）与 `open_entry`（数据流）。接口只接受 `NodeId`，不接受路径字符串，天然无路径逃逸。

## 4. 进程模型：`omnizip-mountd`

- 每用户一个守护进程，托管全部挂载；GUI / CLI 通过单实例同一 IPC 通道发起 `mount` / `unmount` / `list` / `warm`。
- 理由：资源管理器与 Finder 对文件系统响应延迟敏感，UI 进程的渲染与 GC 不应影响；挂载可在 GUI 退出后保持；CLI 无 GUI 也能用；C 引擎（unrar、libarchive）崩溃不波及 UI。
- 生命周期：首次挂载时按需启动；无挂载且空闲 5 分钟自动退出；系统登出时内核清理挂载，守护进程把"上次挂载列表"写入数据库供恢复。
- 线程：每个挂载一个 I/O 线程池（默认 4 线程），解压在工作线程，文件系统回调快速返回（WinFsp 使用异步响应）。
- 守护进程崩溃：内核向应用返回 EIO，GUI 检测到后提示"重新挂载"。
- **当前实施（2026-10-29，Windows）**：`crates/omnizip-mountd`，纯 Rust（不含 WebView），与桌面应用同目录安装。应用首次挂载时启动它：独立进程，不继承应用的句柄、尽量脱离应用所在的作业对象，因此 OmniZip 退出后挂载仍在；"退出时卸载"打开时，带主窗口的 OmniZip 退出才让它卸载全部（资源管理器右键动作的小窗口进程不动挂载）。应用是它的客户端（`apps/desktop/src-tauri/src/mounts.rs`），启动时连上已在运行的守护进程，侧栏照常列出挂载。
  - IPC：命名管道 `\\.\pipe\omnizip-mountd-<用户 SID>`，每行一个 JSON 请求与响应：`mount` / `unmount` / `unmountAll` / `list` / `watch`（保持连接，列表一变即推送）。管道只允许当前用户（与 SYSTEM）连接；客户端连上后先核对管道属主是本用户或 Administrators，其他用户抢先创建同名管道也截不到密码。
  - 列表一变即写入 `mounts.json` 供"启动时恢复"；启动时清理上次异常退出遗留的缓存；没有挂载 5 分钟后自动退出。
  - **以管理员身份挂载**（挂载对话框中的按钮，仅 Windows）：经 UAC 启动 `omnizip-mountd --elevated --handoff <管道>`。应用先在本进程校验密码（错了不必再弹一次 UAC），再经一次性管道把挂载请求（含密码）交给它：管道只允许本用户，且应用核对连上的正是自己启动的进程。它成为提权守护进程（管道名加 `-admin`，带中完整性标签，未提权的应用可以列出与卸载），或把请求转交给已在运行的那个。提权守护进程只接受提权客户端的挂载请求、只挂到盘符：用户的任何程序都不能借它以管理员身份解析压缩包，或把卷放到只有管理员可写的位置。提权挂载经挂载管理器创建全局盘符（§6），不写入恢复列表（启动时不弹 UAC）。

## 5. 按格式的随机访问策略

挂载体验的关键是**随机读**。不同格式差异很大，需要分别处理：

| 格式 | 随机读天然能力 | 策略 |
|---|---|---|
| ZIP（Store）、ISO、TAR（未压缩）、CPIO、CAB（MSZIP 块独立） | 直接 seek | 零拷贝直读，体验最佳 |
| ZIP（Deflate / BZip2 / Zstd，每条目独立压缩） | 条目内只能顺序 | 每个打开句柄维护解码器位置；前向 seek 丢弃数据；后向 seek ≤ 64 KB 用环形缓冲；更远则重开流。检测到反复后向 seek（视频拖动、随机访问数据库文件）→ 后台把该条目完整解压到磁盘缓存并切换为直读 |
| 7z / RAR 固实块 | 必须从块首解到目标条目 | 首次访问某固实块：整块解压到磁盘缓存（< 256 MB 时放内存），块内所有条目随后 O(1)；挂载前提示；可"预热全部" |
| tar.gz | 单一流，无索引 | 首次挂载后台构建 zran 式检查点索引（每 4 MB 保存 32 KB 窗口），持久化到 `cache_dir/mount-index/<blake3(path,size,mtime)>.idx`；索引就绪前随机读走"重解 + 缓存" |
| tar.xz（多块流） | 块级可寻址 | 直接利用 xz 块索引（`xz -T` 产物天然多块）；单块流退化为 tar.gz 策略 |
| tar.zst | 帧级可寻址 | 若带 seekable 跳过帧表则直接利用；否则同 tar.gz 策略 |
| tar.bz2 | 块级（900 KB） | 扫描块边界建索引 |
| 嵌套压缩包 | — | 卷内呈现为普通文件，不递归挂载；用户可对其再次"挂载" |

**当前实施（2026-10-30）**：
- 原样存储的数据（ZIP 的 Store 条目、plain tar）：读取器给出条目数据在压缩包文件中的位置（`ArchiveReader::stored_range`），挂载直接按位置读压缩包，不解码、不进缓存、不经读取器锁。plain tar 列举时按头跳读。
- 各自成流的条目（ZIP 的 Deflate 等、非固实 7z / RAR）：小条目首次读取时整条解进缓存；超过内存缓存上限（8 MiB）的大条目由后台线程解码进缓存文件，读取只等到所要的字节解出即返回，解完照常进入缓存，此后任意位置直读；同一条目的并发读取共用一次解码。环形缓冲与"重开流"未采用：缓存文件本身已能满足回退。
- 固实块（C 类）：首次访问一遍解码，放得下的条目全部进缓存（"后台预热固实压缩包"设置）。
- 单一压缩流（tar.gz / tar.xz / tar.zst / tar.bz2，D 类）：首次访问同样一遍解码、全部缓存（不受预热设置影响，守护进程挂载后即在后台进行）；检查点索引尚未实现，超出磁盘缓存上限的部分仍需从头重解。
- 卷释放时取消正在进行的解码。

缓存：
- 内存块缓存：LRU，默认上限 256 MB（可配置）。
- 磁盘缓存：默认 2 GB 或剩余空间 10%（取小），位置可配置；卸载时清理，可选保留以加速再次挂载。
- 索引缓存：长期保留，按源文件（路径、大小、mtime）哈希命中。

## 6. 文件系统语义

| 方面 | 设计 |
|---|---|
| 名称 | 与解压相同的净化规则；Windows / macOS 默认大小写不敏感，同目录大小写冲突追加 ` (2)`；非法字符替换为 `_` 并在"属性"中显示原名；超长名截断但保留扩展名；文件名编码修复（见 02 §4.3）同样生效 |
| 元数据 | mtime / atime / ctime；Unix mode（Linux / macOS，默认去掉 setuid / setgid）；Windows 上文件不带只读属性（只读的是卷：从卷中复制出去的是普通文件；文件只读还会让写入先报"拒绝访问"），可选 OFFLINE 属性；大小 = 声明的未压缩大小。Windows 上以任意大小写打开的路径报告卷中原本的写法（规范化名称），如 `GetFinalPathNameByHandle`、进程映像路径中 |
| 符号链接 | Linux / macOS：目标在卷内时呈现为符号链接，否则呈现为内容为目标路径的普通文件；Windows：一律普通文件 |
| 硬链接 | 呈现为独立文件 |
| 卷信息 | 卷标 = 压缩包名；文件系统名 `OmniZip`；序列号 = 压缩包哈希前 32 位；Windows 上以**磁盘卷**（`WinFsp.Disk`）呈现、属性为只读介质：与写保护介质相同，以写入、删除、改属性或改安全描述符的权限打开即报"介质受写入保护"，新建、覆盖、改名同样；只要求 `MAXIMUM_ALLOWED` 的打开成功、只能读。盘符优先经挂载管理器创建（`\\.\X:`，全局可见）：只有挂载管理器登记的卷，`GetFinalPathNameByHandle` 才能给出盘符路径，部分程序靠它找到自己的文件；这需要管理员权限或 WinFsp 的 `MountUseMountmgrFromFSD` 设置，否则退回本登录会话的盘符（与此前相同，这类调用报错 1005）。文件夹挂载点不经挂载管理器。原计划的网络驱动器类型不采用：WinFsp 只允许磁盘卷挂载到文件夹，网络卷在资源管理器中的集成还依赖 WinFsp 网络提供程序（2026-10-29 实施时决定） |
| 可写（2026-10-29 实现，Windows） | 挂载对话框中的"允许写入"（默认值来自设置项"可写挂载"）。写入进入临时层（`OverlayFs`，守护进程缓存目录下的 `layer-<id>`），压缩包本身不变：写时复制，档内文件第一次被写入、截断、改修改时间或移动时复制进临时层，此后所有句柄读这份副本；截断为 0 不必先解压；删除或移走的条目记下删除标记并隐藏；在删除处新建的目录不显示旧内容；移动目录时把整棵树复制进临时层。可写卷不带只读介质属性，可用空间为临时层所在磁盘的可用空间；只保留修改时间（属性、其他时间与安全描述符接受后丢弃）。 |
| 卸载与保存 | 有改动时卸载先询问：**保存到压缩包** / **放弃改动** / 取消。系统自行放到卷上的新项不算改动，不保存、也不因它们而询问：根目录的回收站与索引数据（`$RECYCLE.BIN`、`System Volume Information`、`.Trashes`、`.Spotlight-V100`、`.Trash-1000` 等），任意文件夹中的 `desktop.ini`、`Thumbs.db`、`.DS_Store`、`._*`（macOS 资源分支）与 `~$*`（Office 锁文件）；压缩包里原有的同名文件被修改仍会保存，移进回收站的档内文件按删除保存（实测普通挂载时 Windows 不用回收站、直接删除；经挂载管理器的全局盘符可能使用）。保存在应用中作为任务运行（进度、可取消）：守护进程卸载后把临时层移到 `cache/mount-saving`（守护进程从不清理这里）并交给应用，连同改动清单（新建或修改的文件与目录、删除的路径、要从压缩包移除的条目名：显示名因非法字符等与条目名不同时按条目名）。ZIP 原地更新：删除被删除或被替换的条目、加入新文件，未改动的条目原样复制；7z 与 tar 系列解到压缩包旁的临时目录、应用改动、按原格式与固实 / 加密 / 文件名加密 / 注释设置重新打包，完成后替换原文件；RAR、分卷与自解压包不能写回，只能放弃。保存成功后删除临时层；失败时压缩包保持原样、临时层保留。浏览器中打开着的同一压缩包先关闭读取、保存后重新打开。 |
| 退出与异常 | "退出时卸载"跳过有未保存改动的可写挂载，它们留在守护进程里，下次打开 OmniZip 时再决定保存或放弃。"启动时恢复"以空的临时层重新挂载。临时层是临时的：守护进程异常退出、注销或关机后，下次启动时随缓存一起清除 |

## 7. 安全

- **不执行任何内容**，但用户可能在卷内双击可执行文件：首次挂载弹出一次性风险提示；Windows 网络驱动器类型触发 SmartScreen 区域检查；macOS 卷内文件附加 `com.apple.quarantine`。
- **压缩炸弹**：只暴露声明大小；读取时实际输出超过声明大小即截断并返回 EIO；单条目膨胀比上限与解压策略相同；缓存配额限制磁盘占用。
- **超时保护**：任何文件系统回调 > 30 s 返回 EIO 而不是阻塞，避免资源管理器假死；预热作业可取消。
- **路径逃逸**：接口只用 `NodeId`，不存在 `..` 问题。
- **权限**：守护进程以当前用户身份运行；不开启 `allow_other`，其他用户看不到挂载；WinFsp 驱动安装需要一次管理员权限，安装包签名校验。
- **资源上限**：每卷打开句柄 ≤ 4096；每卷内存上限；守护进程总内存上限（默认 1 GB，超出拒绝新挂载）。
- **密码**：`SecretString` + `zeroize`，不写日志、不落盘。

## 8. CLI

```
omnizip mount   <archive> [--at <盘符:|路径>] [--label <名称>] [--rw]
                          [--password-file <F>] [--cache <大小>] [--warm] [--detach]
omnizip unmount <archive | 挂载点 | --all> [--force]
omnizip mounts  [--json]
omnizip mount   <archive> --exec -- <命令…>        # 临时挂载，命令结束后自动卸载
```

退出码：`0` 成功；`20` 后端未安装或未启用；`21` 挂载点被占用；`22` 需要密码；`23` 源文件不可读；`24` 守护进程不可达。

## 9. 设置页"挂载"

- 后端状态与引导：WinFsp 未安装 → 下载安装按钮；FSKit 扩展未启用 → 打开系统设置；`fusermount3` 缺失 → 安装命令提示。
- 默认挂载位置策略（盘符范围 / 目录）。
- 缓存上限与位置、索引缓存清理。
- 退出时自动卸载、启动时恢复挂载、固实包预热策略、OFFLINE 属性开关、可写挂载（挂载对话框"允许写入"的默认值）。
- 已挂载列表（与侧栏同源）。

## 10. 性能目标

| 指标 | 目标 |
|---|---|
| 挂载完成（10 万条目 ZIP） | < 1 s |
| 目录列举 1 万项 | < 50 ms |
| 顺序读吞吐（Store / Deflate） | ≥ 解压吞吐的 80% |
| 缓存命中读延迟 | < 1 ms |
| 视频拖动（Deflate ZIP 内 2 GB MP4） | 首次回退 ≤ 2 s 切换落盘，后续即时 |
| 固实 7z 1 GB 块首次访问 | 与解压该块耗时相同，UI 有进度 |

**实测（2026-10-30）**：`cargo run --release -p omnizip-mount-winfsp --example mountbench -- <压缩包> [--writable]`，经真实 WinFsp 驱动用普通文件 API 测量。Windows 11、32 线程、NTFS，release 构建在项目目录外运行，Defender 实时防护关闭（原因见下），误差约 ±10%。数据集同 11 §8.4：小文件组 14,891 个文件 / 208 MB，大文件组 4 个文件 / 847 MB（最大 392 MB）。

| 场景 | 优化前 | 现在 | 参照 |
|---|---|---|---|
| 挂载 + 列出小文件组全部条目（ZIP） | 0.02 + 0.2 s | 同左 | 目标 < 1 s |
| 小文件组首次读完：ZIP / 固实 7z | 3.6–4.0 / 1.9 s | 同左 | 解压 4.5 / 3.9 s |
| 小文件组首次读完：tar.gz / plain tar | 平方级（tar.gz 估计约 1 小时） | 2.4 / 2.0 s | 解压 4.2 s |
| 大文件组：392 MB Deflate 文件的首字节 | 0.52 s | 1 ms | — |
| 大文件组首次读完：ZIP Deflate | 528 MB/s | 860 MB/s | 解压 1.3 GB/s（4 个条目并行） |
| 大文件组首次读完：ZIP Store / plain tar | 约 530 MB/s（整条解进缓存） | 1.7 GB/s，首字节即时 | — |
| 大文件组再次读完 | 1.9 GB/s | 3.2 GB/s | — |
| 缓存命中的 4 KiB 随机读 | 14–20 µs | 同左 | 目标 < 1 ms |
| 可写层：新建 / 删除 2000 个 16 KiB 文件 | 0.98 / 0.79 s | 0.64–0.72 / 0.39–0.45 s | NTFS 0.37–0.43 / 0.18–0.19 s |
| 可写层：写 512 MiB / 读回 | 0.19 / 0.31 s | 0.15 / 0.16 s | NTFS 0.12 / 0.05 s |

Defender 实时防护：文件在挂载盘上第一次被打开时同步扫描。开启时小文件组首次读完需 43–64 s（扫描进程 MsMpEng 占约 2 个核，基准进程只占 5–10%），关闭后 3.6 s；再次读取命中扫描缓存，不受影响。新建文件也会被扫描（开启时 2000 个文件 8.4 s）。这是系统行为，OmniZip 不改用户的防护设置。

同期修复：一个卷同时打开的句柄上限原为 4096，而 Windows 缓存文件数据期间，程序关闭的文件要等缓存放手才真正关闭，连续读取四千多个文件（如从挂载盘复制一个大文件夹）就报"打开的文件过多"，现提高到约一百万。
