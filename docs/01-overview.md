# 01 · 产品概述与目标

## 1. 产品定位

OmniZip 是一款跨平台桌面压缩软件，目标是在 Windows、macOS、Linux 三大平台提供**一致、现代、对中文用户友好**的压缩/解压体验，同时具备 7-Zip 级别的格式覆盖与命令行能力。

对标产品与借鉴点：

| 产品 | 借鉴 | 规避 |
|---|---|---|
| 7-Zip | 格式覆盖、压缩率/速度基准、CLI 参数体系 | 过时的界面、无主题 |
| WinRAR | 多卷、恢复记录、解压向导心智 | 商业许可、仅 Windows |
| Bandizip | 中文文件名乱码自动修复、"智能解压"、右键菜单设计 | 广告、闭源 |
| PeaZip | 跨平台、格式广度 | 界面陈旧、性能一般 |
| Keka / The Unarchiver | macOS 原生体验、拖放、Finder 集成 | 格式写入能力有限 |
| Ark / File Roller | Linux 桌面集成（Dolphin/Nautilus） | 界面受桌面环境约束 |
| Windows 内置 ISO 挂载 / macOS 磁盘映像 / Pismo File Mount | "挂载即用"的心智：不解压直接把包当磁盘 | 只支持镜像格式或仅单平台 |

## 2. 目标用户

| 用户 | 典型任务 | 对设计的要求 |
|---|---|---|
| 普通用户 | 双击打开、右键解压到此处、拖放压缩 | 零学习成本、默认值即最佳、乱码自动处理 |
| 高级用户 | 调压缩参数、加密、分卷、批量转换格式 | 参数完整但折叠、预设可保存 |
| 开发者 / 运维 | 脚本、CI、管道流式处理、JSON 输出 | CLI 完整、退出码稳定、可无 GUI 运行 |

## 3. 核心需求到方案的映射

| 需求 | 方案要点 | 文档 |
|---|---|---|
| 多平台 | Tauri 2 + Rust 单代码库；平台差异封装在 `platform` 层与独立的 Shell 扩展工程 | 02、07 |
| 多语言 | ICU MessageFormat、运行时切换无需重启、RTL 预留、Shell 菜单与 CLI 同步本地化 | 06 |
| 多主题 | 三层设计令牌、Light / Dark / System / 高对比、JSON 自定义主题、系统强调色、窗口材质 | 05 |
| 多格式 | 统一 `ArchiveFormat` 抽象 + 可插拔引擎；格式按 Tier 分级承诺 | 03 |
| 界面美观大气 | 自绘标题栏、留白网格、单一强调色、虚拟化列表、克制动效、系统字体 | 04 |
| Shell 操作 | 三平台右键菜单 + 文件关联 + 默认程序 + `omnizip` CLI + Shell 补全 | 07、08 |
| 直接挂载 | 任意可读格式一键挂载为虚拟卷（Windows 盘符、macOS /Volumes、Linux FUSE），内容按需解压 | 12 |

## 4. 平台支持矩阵

| 平台 | 最低版本 | 架构 | 分发渠道 |
|---|---|---|---|
| Windows | 10 1809+（完整体验需 11） | x64、ARM64 | MSIX（主）、EXE/MSI、winget、Scoop |
| macOS | 12 Monterey+ | Universal（x86_64 + arm64） | DMG（主）、Homebrew Cask、App Store（后续） |
| Linux | glibc ≥ 2.31（Ubuntu 20.04+、Fedora 36+） | x64、ARM64 | AppImage、.deb、.rpm、Flatpak、AUR |

WebView 依赖：Windows 使用系统 WebView2（Win11 内置，Win10 由安装器引导）；macOS 使用 WKWebView；Linux 使用 WebKitGTK 4.1。

## 5. 功能范围（v1.0）

必须（Must）：
- 浏览、解压、创建、测试 ZIP / 7z / TAR 系列 / gz / bz2 / xz / zst；只读 RAR
- 压缩包内目录树导航、搜索、排序、多选、拖入添加、文件预览
- 密码（AES-256）、7z 文件名加密、分卷、固实
- 智能解压、覆盖策略、批量解压多个压缩包
- 文件名编码自动识别与手动切换
- 明暗主题 + 跟随系统 + 至少 4 套内置主题
- 简体中文、繁体中文、英文、日文起步，架构支持无限扩展
- Windows 右键菜单（Win10 经典 + Win11 现代）、macOS Services、Linux 主流文件管理器菜单
- 文件关联与"默认程序"注册
- 完整 CLI
- 挂载：任意可读格式挂载为只读虚拟卷，像 ISO 一样出现在文件管理器侧栏并可弹出

应该（Should）：
- 任务中心、任务栏/Dock 进度、系统通知
- 拖出到资源管理器 / Finder（原生 drag source）
- 自动更新（非商店渠道）
- 自定义主题导入导出

可以（Could，v1.x）：
- 主题编辑器、沙箱 Worker 进程、SFX 自解压创建、格式转换向导、Quick Look 预览插件、ZIP 可写挂载（卸载时回写）

## 6. 非目标（v1.0）

- 云盘 / 网络协议直连浏览
- 备份计划任务
- 替代文件管理器
- 移动端

## 7. 成功指标

| 指标 | 目标 |
|---|---|
| 冷启动到可交互（SSD） | < 1.0 s |
| 打开含 10 万条目的 ZIP 到列表首屏 | < 1.0 s |
| 解压吞吐（同算法同线程） | ≥ 7-Zip 的 90% |
| 安装包体积（Windows） | < 30 MB |
| 空闲内存（含 WebView） | < 120 MB |
| 右键菜单项渲染延迟 | < 50 ms |
| 挂载 10 万条目 ZIP 到文件管理器可见 | < 1.0 s |
| 中文乱码文件名自动识别准确率（内部测试集） | > 98% |
| 崩溃率（周活用户） | < 0.1% |

## 8. 决策记录与开放问题

已决定（2026-10-27）：

| 事项 | 决定 | 影响 |
|---|---|---|
| 许可证 | **MIT** 开源 | 符合 WinFsp 的 FLOSS 例外，可直接使用；unrar 仍需隔离为单独 crate 且仅解压；所有依赖需与 MIT 兼容（`cargo-deny` 许可证白名单） |
| 名称 | 暂定 **OmniZip**，后续按需更改 | 产品名、Bundle ID、ProgID、D-Bus 服务名、URL scheme 等品牌字符串集中在 `platform/branding.toml`，便于整体替换 |
| 商业模式 | 完全开源 | 不设 Pro 功能；默认零遥测；更新与发布走公开渠道 |
| macOS 挂载后端 | M0 实测 FSKit 对虚拟文件系统的支持程度后再选 | 实测清单见 12 §12；NFS 回环为保底方案 |

仍待确认：
1. **团队技能**：方案默认团队具备 Rust + TypeScript；若 C++/Qt 更强，参见 02 中的备选方案。
2. **商标检索**：发布前对最终名称做一次检索。
